# PilotDeck 周报模板

> 每周一 08:00 (Asia/Shanghai) 生成  
> 范围: 上周一 ~ 本周日（UTC+8）  
> **关键要求**: 竞品动态必须详细（每家 T1 都要有具体 release/媒体/数据，不能空话）

## 报告结构

```markdown
# PilotDeck 周报 | YYYY-MM-DD ~ YYYY-MM-DD (第 N 周)

> 本期要闻 (1-2 句话)

## 1. 本周核心动态 (5-8 条带数据)
- 时间锚定的事件 + 关键数据/数字

## 2. 仓库活跃度
- 本周 commit 数、PR 合并数、issue 数
- 增长率、与上周对比

## 3. 重点 issue / PR 复盘 (表格)
- 至少列 5 个重要 PR
- 类型分类：Feature / Fix / Docs

## 4. 媒体与社区
- 至少 3 家媒体报道
- 核心叙事
- 社区反馈

## 5. 竞品动态 (T1 直接对标) — 【必须详细】
对每个 T1 竞品单独成节，包含：
- **产品名 + 厂商**
- **本周关键动态** (具体数据/release 链接)
- **历史里程碑** (首次出现、关键版本、商业化进展)
- **对 PilotDeck 的启示** (机会/威胁/借鉴)

**T1 必覆盖**:
- Claude Cowork (Anthropic)
- Skywork 桌面版 (昆仑天工)
- BitFun CoWork (开源)
- OpenClaw (NousResearch)
- 国内其他: QoderWork / MiniMax Agent / 阶跃 / QClaw

## 6. T2 框架层动态 (简洁表格)
- 6 个主流框架本周是否有 release/star 变化
- 一句话判断

## 7. 风险与机会信号
### ⚠️ 风险 (5 条带数据)
### 🟢 机会 (5 条带数据)

## 8. 下周关注点 (5 条)
- 具体可观察的事件

---
数据来源
生成时间
追踪者
```

## 飞书简版（推送到群）

- 标题 emoji + 1-2 句要闻
- 关键数字加粗
- 竞品动态用折叠结构（每个 T1 一行）
- 不超过 1500 字（在飞书卡片里显示友好）
- 末尾附完整版路径

## 内容深度要求

- ❌ 不要"持续主导"、"保持领先"这种空话
- ✅ 必须有 release 日期、版本号、star 数、定价等具体信息
- ✅ 每个 T1 竞品都要有"对 PilotDeck 的启示"——机会/威胁/借鉴
- ✅ 风险和机会必须带数据支撑
